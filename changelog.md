- `openclaw/` — new folder. `README.md` is the write-up: what the source is (a **messaging gateway with an assistant in it** that grew a coding agent, which is why the prompt is assembled per *surface*), the four different things 2.0 ships that could be called "team", a per-topic mapping onto every existing doc in this collection, and twelve findings that are new here
- `openclaw/system-prompt-main.md` — the `promptMode: "full"` prompt section by section in render order, each with its gate, plus the `minimal`/`none` variants. The prompt carries a **declared cache boundary in its own text** (`<!-- OPENCLAW_CACHE_BOUNDARY -->`); the stable prefix above it is memoised on a hash of its inputs and section placement is argued in code comments as a caching decision. Provider plugins may replace exactly three named sections and inject on either side of the boundary. Also records a docs/source drift: `docs/concepts/system-prompt.md` documents an **OpenClaw Self-Update** section, twice, that exists nowhere in the source
- `openclaw/workboard.md` — the team-coding answer, and the only **durable claimable board** in this collection rather than a call graph: claim tokens redacted in every projection and handed out once, but deliberately *not* required by the recovery paths; heartbeats with a `running_without_heartbeat` diagnostic; a completion contract whose violation is a first-class card event (`workboard_protocol_violation`); a dependency DAG whose `## Parent results` section renders each done parent's summary into the child's brief; `## Recent done work by <agentId>` as per-assignee episodic memory scoped to a board; and a dispatcher that starts **one card per owner per pass and skips owners with work in review** — a Kanban WIP limit applied to agents. The worker prompt is six lines. Its docs are unusually honest that "proof statuses are worker-reported outcomes, not independent verification"
- `openclaw/system-prompt-subagent.md`, `openclaw/tool-descriptions.md` — the sub-agent context block, the runtime-generated `## Active Subagents` roster injected into parent turns so nothing has to poll, and verbatim tool descriptions. Findings for `agent-tool-implementations.md`: `read` has a **within-line `cursor`** as a third continuation axis (the cleanest answer yet to the minified-file problem); the three-consumer structure is *named* in the type (`description` / `label`+`displaySummary` / `promptSnippet`+`promptGuidelines`); `exec` **renders the host's approval allowlist into its own description** on Windows; and `AGENTS.md` forbids static cross-tool references outright ("gating turns the reference into hallucination bait"), which is why every description is a builder

The per-turn skill review is handed an **"authoritative runtime receipt"** of which skills actually fired, budgets mutations explicitly, and states its own expected answer ("NO_REPLY is the correct answer for most turns"). Compaction validates five required headings *in the post-budget text* and **fails closed**, keeping the original history when no attempt passes

Second pass: turned the OpenClaw read into design work. The question that started it — "is Workboard a subagent orchestration framework?" — has the answer "no, it's the layer above one", and that distinction turned out to name a gap in this design.

- `agent-design/orchestration.md` — new: **the run ledger**, the layer above a run that the design was missing. Every run here is one-shot; nothing recorded that the *task* existed. Three `future.md` items (task splitting, the PR-steward loop, generalized suspension) were each blocked on part of the same object, so they are one table rather than three subsystems. Specifies the task record with frozen `scope` and stored authority, an eight-state lifecycle where `handoff` (not `review`, since this design never commits) counts as occupied for concurrency, a deterministic dispatch pass, harness-held **leases instead of agent-facing claim tokens** (our runs are dispatched, not self-claiming — so the harness takes the lease before the run starts and settles it from the `Complete` report, keeping the tool surface unchanged and removing an injection surface), and health as **queries over stored fields**. Task splitting lands as `Complete.report.spun_off` with exactly two relations: `follows_this` and `blocks_this` — the second answering `future.md`'s open "what does the originating run do while it waits" as **nothing; it ends, and the task waits**
- **§8 argues the oversight position**: no supervisor run, for four reasons, the sharpest being that task titles and attempt summaries are written by runs that read untrusted ticket and PR text, so a supervisor reading them to decide what runs next would let untrusted content **choose the next run** — reach nothing else in the design grants. It also states the role invariant explicitly for the first time — **a role may file, propose or report; it may not act on what it oversees** — promoted from pattern to rule by reading it across five independent OpenClaw roles (Custodian proposes config and a human applies; the exec reviewer can allow or escalate but structurally cannot deny; ClawSweeper "recommends with evidence, never executes the close"; the skill reviewer emits pending proposals; memory consolidation places supplied entries but never authors prose)
- `agent-permissions-approval.md` — new **§2a, the consent-assertion problem**: the seam where a model asserts that a human approved something, which the self-assigned-boolean sources (Windsurf, Replit, Cline) leave wide open and which suspend/resume makes *worse*, since a resumed run reads the human's reply as text in its own context. OpenClaw's Custodian is the only source in the collection that closes it — a first call designed to fail ("it is safely denied and registers the proposal"), a per-action-class channel binding ("Delegated changes need operator UI approval; never ask for a chat yes for those"), and the load-bearing clause: **"The host independently verifies their consent; never set approved=true without it."** §2 also gains OpenClaw's exec auto-reviewer, whose `allow|ask` verdict enum — no deny path — makes it the only reviewer here that degrades to asking a human rather than suppressing work
- `agent-design/README.md` — five decision rows (the ledger; non-model oversight; file-don't-stretch; the role invariant; and where the ledger lives, recorded as **open** rather than decided) and the reading-order entry
- `agent-design/future.md` — task splitting and the PR-steward loop marked superseded, original statements kept per this folder's supersession discipline; `agent-design/medium.md` §4c narrowed: a *parked task* is now the default answer to "wait for X" and `AwaitEvent` narrows to the transcript-must-survive case it names as its real purpose. `AskUser`'s own suspend/resume is explicitly unaffected
- `openclaw/README.md` — records which integrations have landed and which are still scoped

Tenth pass: a terminology question — "is a lens the same as a tool or a subagent?" — surfaced a defect in the ninth pass and a wrong claim in its changelog entry.

Both fields are model-supplied enums the harness maps to a tool set, so the pair gates exactly as structurally as the type — widening the key rather than minting a fourth sub-agent type keeps one reviewer core parameterised by lens instead of fracturing it. `Task`'s `role` enum gains `visual`

Sixth pass: generalised the artifact work into a single address space, which removed two planned tools and absorbed three vocabularies the design had been growing separately.

- `agent-design/artifacts.md` — substantially rewritten around **one ref grammar** (`<scheme>://<locator>[:<selector>]`, bare path as working-tree shorthand) spoken by every read tool: working tree, `file://`, `git://`, `dep://`, `artifact://`, `run://`. The framing changed from "a store attachments go into" to "one half of an address space, the other half being that anything readable is named by a ref." **There is deliberately no `http(s)://` scheme, and that absence is the security property** — every scheme resolves through a configured resolver that never takes a hostname from the model, which keeps the SSRF discipline structural rather than a validation rule. `Read` becomes a **converting reader** (PDF pages, spreadsheet sheets, docx, html, archive members, notebooks, and images as OCR) with every conversion announced, because OCR'd text and a real PDF text layer are not equally trustworthy.
