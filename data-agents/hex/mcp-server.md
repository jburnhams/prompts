# The Hex MCP server and its Claude connector

*Read 2026-11-12. Tags as in [`README.md`](./README.md).*

## 1. Shape

- **One remote endpoint**: `https://app.hex.tech/mcp`, or the workspace's
  own host for single-tenant, EU and HIPAA stacks (`eu.hex.tech/mcp`).
  Streamable HTTP, OAuth per user. [docs]
- **Unauthenticated behaviour** [probe]: a JSON-RPC `initialize` POST
  returns `401` with
  `WWW-Authenticate: Bearer error="unauthorized", error_description="Authorization needed", resource_metadata="https://app.hex.tech/.well-known/oauth-protected-resource"`,
  and that document is
  `{"resource":"https://app.hex.tech/mcp","authorization_servers":["https://auth.app.hex.tech"],"bearer_methods_supported":["header"]}`.
  So the MCP authorisation spec's discovery path (RFC 9728) with a
  separate authorisation server. Nothing, including the tool list, is
  served before auth.
- **Clients documented**: Claude (directory connector), Claude Code,
  Cursor (marketplace plugin, `app.hex.tech` only), ChatGPT (directory
  app, `app.hex.tech` only; custom hosts through Developer Mode), Codex
  (plugin), Glean (admin-configured, "Streaming HTTP", "OAuth User"),
  Figma's design agent, and "most standard MCP clients". [docs]
- **Plans and roles**: Team and Enterprise; Explorer role for the
  knowledge tools, Editor for the project tools. [docs]
- **MCP access is outside the API switch**: "Turning off API access for
  the workspace, or revoking it for an individual user, does not disable
  MCP access. To revoke all of a user's access, deactivate the user."
  [docs] An admin who disables the API to stop agents has not stopped
  them. [inference]

## 2. The tools, in two tiers

Names and contracts as documented. Schemas are not public.

**Knowledge tools (Explorer and above)** [docs]

| Tool | Input | Output | Notes |
|---|---|---|---|
| `search_projects` | query | `projects[]`: `projectId`, `title`, `description`, `generated_summary`, `url`, `type` (`"project"` or `"app"`) | Returns published *and* unpublished projects. "The response structure and fields … are subject to change." |
| `create_thread` | the question | "Confirmation message with Thread ID and Thread URL" | Starts a Hex agent run. "Threads typically take several minutes to complete." The agent picks connections itself; sensitive ones are excluded unless an admin allows them. |
| `get_thread` | Thread ID | Running: ID, status, **wait time**. Done: recent messages, "any charts, tables, or visualizations generated by the agent", a link | "designed to be called multiple times until the Thread reaches idle status". Reports each chart's cell ID. |
| `continue_thread` | Thread ID, prompt | — | "You can only continue a Thread once it has finished running." MCP threads are "always new, standalone": you cannot continue a thread started in the Hex app, or start one on an existing project. |
| `get_me` | none | user ID, name, email, role, workspace ID | "Useful for confirming which workspace an agent is connected to, and which role it is operating under." |

**Project editing tools (Editor and above)** [docs]

| Tool | What it does | Detail worth keeping |
|---|---|---|
| `create_project`, `get_project` | create; read metadata | `get_project` omits sharing metadata unless asked |
| `list_cells`, `get_cell` | read the **draft** | Page size 25, max 100. `contents` holds `codeCell`, `sqlCell`, `markdownCell`, "All three are always present; the one matching the cell's type holds a `source`". Other cell types (charts, inputs) come back with type and label only. **The list is flat**: "an agent cannot read a notebook's nesting back out, even though `create_cell` can place a new cell inside a section." |
| `list_data_connections` | resolve a connection by name | Tip: reuse the `dataConnectionId` of an existing SQL cell |
| `create_cell`, `update_cell`, `delete_cell` | edit the draft | SQL cells take a connection ID **or** a flag to query other cells' results, not both. Labels are create-only. "There is no separate staging step, so changes are immediately part of the notebook that collaborators open." |
| `run_cell`, `run_notebook` | async run | `run_cell` runs upstream dependencies too and has a **dry run**. `run_notebook` reuses cached SQL by default. |
| `get_run` | poll | Terminal states `COMPLETED`, `ERRORED`, `KILLED`, `UNABLE_TO_ALLOCATE_KERNEL`. "Poll … every five seconds." |
| `get_cell_output` | a SQL cell's latest preview | Reports row limit, rows returned, total rows and a truncation flag, "so an agent can tell when it is not seeing the full result. Columns are never dropped." |
| `get_cell_image` | PNG of a run chart cell | 100–2000 px, both sides or neither. "the default image is tens of kilobytes, while a dense chart at the maximum 2000x2000 can exceed 500KB. Request one chart at a time." |

Two cautions the docs spell out, both of which this collection has
discussed in other forms:

- **A run handle that is not a run.** "The `runId` identifies the
  long-running draft session, not a single execution, so it can
  correlate with earlier runs of the same project. … confirm the
  reported start time is at or after your request before trusting that
  the run has finished — and after editing a cell, confirm the output
  you read reflects the new source rather than the previous execution."
  [docs] The fix is pushed onto the client. [inference]
- **Read before write.** "Calling `get_project` and `list_cells` before
  `update_cell` or `delete_cell` avoids edits against a stale view of
  the notebook." [docs] Advice, not enforcement: no version or
  precondition argument is documented. Compare the stale-hash rejection
  in `../../agent-design/medium.md`. [inference]

Three of the tools were added later than the rest: the changelog of
2026-09-15 announces "`create_project`, `get_project`, and
`update_project`". `update_project` is not in the current docs.
[changelog, docs]

## 3. Sensitive connections: a policy per surface

[docs] Admins mark each data connection **Standard** or **Sensitive**
"so the Hex Agent treats them carefully in Threads started outside of
the Hex app", because "a casual question in Slack or an MCP chat could
route analysis against data you'd rather keep off those surfaces".

- MCP, the public API and the CLI share one switch, **off by default**:
  they "can only query connections marked **Standard**", and cell
  outputs and chart images from projects that use a sensitive
  connection cannot be read. Listing, editing and running still work.
- Slack has its own switch, with a middle option: use the connection
  but "only send a link to the thread, rather than posting directly to
  Slack" (changelog 2026-07-30).
- **The surface that starts a thread fixes its policy for life**: "If a
  Thread is started or continued through MCP, API, or CLI, this setting
  applies to the whole Thread — including later messages sent from the
  Hex app."
- Some OAuth connections "are locked as **Sensitive** because query
  results cannot be shared with other users."

This is a data-classification rule keyed on **where the answer will be
read**, which is a different axis from who is asking. [inference]

## 4. The Claude connector: an MCP App in front of a run

**What is documented** [docs, changelog 2026-03-03, blog 2026-01-26]:

- Searching projects returns "visual project cards that display the
  project title, description, and other information, including a link".
- Asking a data question starts a Thread, and "An interactive widget in
  the Claude chat will appear and show the Hex Thread's 'thinking' steps,
  allowing you to follow along with the Thread in real time". Each
  thinking block can be opened "to understand what specific actions the
  Threads agent took"; the changelog adds "see which tables or semantic
  models the agent is referencing, and to spot-check the underlying SQL".
- "The Hex Connector will continually make `get_thread` calls without
  user prompting, checking in on the progress of the Thread."
- "If the Threads agent creates any charts or tables in the course of
  its analysis, the Hex Connector will surface these as a carousel in an
  interactive widget." Charts are "custom-styled" from the workspace;
  users can "hover over a chart to view specific data points" and "copy
  data into your next slide deck or spreadsheet". [blog]
- "Once the Thread has finished its analysis, Claude will summarize its
  key findings and provide a link to the Thread in your Hex workspace. If
  you ask a follow-up question, the Hex Connector in Claude will use a
  `continue_thread` tool call."
- "Interactive widgets … including thinking blocks and chart carousels,
  will expire after 24 hours."
- "Responses inherit the context and access controls from your Hex
  workspace." [blog]
- Shipped in the MCP Apps launch batch, 2026-01-26. [blog]

**What is not documented, and the likeliest reading** [inference]:

- *Who drives the polling.* "Without user prompting" is ambiguous: the
  model may be calling `get_thread` in a loop, or the view may be
  calling it as an app tool. The docs' wording ("the Hex Connector will
  … make `get_thread` calls") and the fact that the model later
  "summarize[s]" suggest the model receives at least the final
  `get_thread` result. A view polling an app-only status tool, the
  shape `../../agent-interactive-views.md` §5 calls a run behind a
  view, would not cost model turns; nothing here says which Hex does.
- *What reaches the model.* `get_thread` returns "any charts, tables, or
  visualizations". Whether that means rows in `content`, rows only in
  `structuredContent`, or cell references is not stated. The existence
  of `get_cell_image` "for clients that don't support those widgets, and
  for agents that need to reason about a chart's appearance" suggests
  the chart *data* is not otherwise in the model's view, but that is a
  guess.
- *Why 24 hours.* The widget renders from the result, and the expiry
  suggests the view fetches signed or cached content from Hex that is
  retained for a day, rather than holding the chart in the transcript.
  Consistent with "store on your server anything that you need to keep"
  in Claude's MCP Apps docs (`../../mcp-apps/data-analysis.md` §4).
- *Citations.* Claude's announcement says "citations"; Hex's pages
  don't. Either the thinking-step drill-down is what Anthropic called
  citations, or the summary links back into cells. Not resolvable from
  docs.

**Behaviour in other hosts** [docs]: ChatGPT, Cursor, Codex, Glean and
Figma get the same tools; nothing says they get widgets. "Some MCP
clients, including Claude, render Hex charts natively in an interactive
widget. `get_cell_image` is most useful for clients that don't support
those widgets." That is the text-fallback rule (`../../mcp-apps/data-analysis.md`
§5 rule 6), implemented as a separate tool rather than as a fallback
inside the result.

## 5. Discrepancies between sources

| Claim | Source A | Source B |
|---|---|---|
| Number of tools | Claude directory: **4** (`search_projects`, `create_thread`, `get_thread`, `continue_thread`), "Added November 2025" | Hex docs: **5 knowledge + 13 project tools** |
| Project tools | Changelog 2026-09-15: `create_project`, `get_project`, `update_project` | Docs: no `update_project`; cell-level tools instead |
| 4.0 projects via MCP | 4.0 docs: "creating, editing, and publishing projects are all now possible via the MCP"; prompt the agent for "4.0 project tools" | MCP docs: no 4.0 tools, and edits "do not modify published app versions" |
| Claude must refresh | 4.0 docs: "The plugin may need to be refreshed … `Refresh tools list`" | — |
| Codex | 4.0 docs: "Codex bundles their plugins as static snapshots of MCP tools, … you may be using outdated tools" | MCP docs: "Install the Hex plugin" |

The last three rows are the same finding: **a host's cached copy of a
server's tool list goes stale**, and Hex works around it by telling
users to refresh or to bypass the plugin. Directory listings lag too.
[inference] That bears on `../../agent-design/keel/tools-and-agents.md`
§4a, where `:discover` stores the tool list with digests and a template
version pins one: the pin is right for reproducibility, and Hex's
experience says the re-discover path needs to be easy.

## 6. Other agent surfaces on the same agent

- **Slack**: the same Threads agent, with its own sensitive-connection
  setting; it can "read the whole Slack thread before it answers"
  (changelog 2026-08-11). [changelog]
- **CLI** (`hex`, proprietary, macOS and Linux): `hex thread create`,
  `thread get`, `thread messages`, `context preview/publish`,
  `eval run/get`, `suggestion list/get/update`,
  `context semantic-project pull`, and `install agent-skill --claude |
  --codex | --path`. "CLI tool calls do not currently consume Credits."
  [docs]
- **API**: thread and topic export (`GetThread`, `ListThreads`,
  `GetThreadMessages`, `ListTopics`), agent usage and credit spend
  (Enterprise). [docs, changelog 2026-10-22]
- **Inbound MCP**: the Hex agent is also an MCP *client*. "External Apps"
  (beta) lets admins enable Notion, Linear or "+ Custom MCP server";
  "Each tool call must be **approved in the conversation** before it
  runs", and External Apps are "Not available from the CLI, API, or
  other headless entry points". [source: `hex-skills`
  `references/advanced-context.md`]
